# 收录说明

**[← 回到首页](../README.md)**

> **本页已随 0.4.0「市场与插件分离」重写。** 旧的「收录快照」——`collection/` 目录、
> 不可变快照、`manifest.json`、收录规范——**整块搬去了插件集合仓库**
> [`HaydenSmith1121/dsh-plugin-collection`](https://github.com/HaydenSmith1121/dsh-plugin-collection)。
> 本页说明：那些内容现在在哪、本仓库里的「收录」变成了什么、以及怎么新增一条。

## 二、本仓库里的「收录」现在是什么

本仓库不再做字节层面的收录，只做**目录与判定**。

> ★ **0.5.0 去掉了信任分级。** 以前这里有一张「已验证 / 已审核」的对照表，
> 现在没有了 —— 目录是一份平铺列表，不替用户给插件分等级。
> 理由见 [README 的「不分级的目录」](../README.md#tiers)：分级回答的是「维护者该不该背书」，
> 而用户要回答的是「这个插件我这儿装不装得上」，后者由**装前检查**当场判，比标签准且不会过期。

留下来的两件事实仍然要分清楚（它们不再是「层级」，只是不同的**来源**）：

| | **本仓库托管字节**（`install.method: tarball`） | **装的是上游产物**（npm / GitHub） |
|---|---|---|
| 回答的问题 | 「**这份字节**在我们这一版 dsh 上实测过吗」 | 「这个第三方插件我们看过吗、怎么装」 |
| 事实来源 | 集合仓库 `manifest.json`（+ 市场自己那一条由 `catalog/overrides/self.json` 声明） | `catalog/overrides/curated.json`（人工核对过的条目）或公开索引 |
| 记录了什么 | tarball 的 `url` / `sha256` / `bytes` / `dshVersion`、peer 结论 | 安装规格 / peer 结论 / 当时怎么验的（`notes` 里），**不含字节** |
| 字节由谁保证 | 集合仓库的不可变快照 | **上游仓库自己** —— 本仓库不重新分发 |
| 装前检查的强度 | 能逐字节看清候选包声明了什么 | 只能对上游仓库做静态探测 |
| 怎么产生 | 集合仓库里放 tarball + 改 `plugin.json` + `build-manifest.mjs` | `market-review.mjs` 探测 → 真机实测 → 人工填写 |

完整字段见 [`docs/插件清单与来源.md`](./插件清单与来源.md#fields) 与
[`docs/目录同步.md`](./目录同步.md#sources)。

> **人工核对的门槛没有降低。** 往 `curated.json` 里加一条的最低要求仍然是
> 「真机隔离环境里装一次、起得来、留下证据，并且把 peer 结论写清楚」，
> 见 [`docs/目录同步.md` §七](./目录同步.md#add-reviewed)。
> 区别只在于：这些记录**不再让条目升级成一个层级**，它只是补上公开索引里查不到的事实。

## 三、不可变快照解决的问题，现在由谁挡

上游发新版之后可能出现这四类情况 —— 这也是当初做收录快照的全部理由：

| 上游发生的动作 | 对用户的后果 | 现在由谁挡 |
|---|---|---|
| 撤回旧版本（unpublish） | 老用户重装时**装不回来** | 集合仓库 `snapshots/<id>/<插件版本>/`（自研 6 个插件） |
| 用同一版本号重新发布不同内容 | 装到的**和当初验证过的不是同一份** | 同上：`manifest.json` 里的 sha256 是冻结的，改了就对不上 |
| 收紧 `peerDependencies` | 原本可用的 dsh 版本**突然装不上** | 目录里的 `peerRuntimePin` / `peerVerdict` + 装前闸门 |
| 改动包结构（挪 `lib/`、去掉 `cordis.patch.yml`） | 装上了但**GUI 里没有** | 装前闸门读 tarball 静态检查；`dsh.bundle.patch` 缺失是致命项 |

**第三方插件这一路是刻意的例外**：本仓库不再打包、也不快照它们的字节，因此
「用同一个版本号重发不同内容」这类风险由**上游**承担。换来的是两件更值钱的事 ——
不再有「我们分发的副本和上游不一致」的问题，且原作者随时可以撤回自己的代码。
第三方插件的可信度靠的是**审核证据**（`review.evidence` 里记录了验证时的 commit），
以及安装时由市场面板校验的 sha256（若该规格提供）。

## 四、完整性校验怎么跑

| 校验什么 | 命令 | 在哪跑 |
|---|---|---|
| 目录与生成器是否一致（逐字节）、索引是否与配置文件派生结果一致 | `node scripts/sync-catalog.mjs --check` | 本仓库；`verify.yml` 每次 push / PR 都跑 |
| 配置文件份数 == 索引条数 | `node scripts/sync-catalog.mjs --check` 之后的 `counts.total` 比对 | 同上（`verify.yml` 的 `catalog` 任务） |
| 市场插件产物是否与源码一致 | `node plugins-src/dsh-plugins-market/build.mjs` + `git diff --quiet -- plugins/` | 本仓库；`verify.yml` 的 `market` 任务 |
| 快照字节是否被改写、`plugin.json` 与清单是否一致 | `node scripts/build-manifest.mjs --check` | **集合仓库**（它的 CI） |

> `dsh plugin add` 本身**不校验 sha256**。tarball 的校验发生在市场面板的装前闸门里
> （下载后核对配置文件记录的 sha256，不一致就是致命项）；手动安装时请自己核对
> 集合仓库 `README.md` / `manifest.json` 里的值。这条规矩与旧版一致。

## 五、怎么新增一条

| 你想做 | 去哪做 | 动作 |
|---|---|---|
| **自研插件发新版 / 新增自研插件** | **集合仓库** | 放新 tarball（**绝不覆盖旧的**）→ 改 `plugins/<id>/plugin.json` 的 `versions[]` 与顶层字段 → 新增一套 `snapshots/<id>/<插件版本>/` → `node scripts/build-manifest.mjs`。**本仓库不用动**，下一轮每日采集会自动把版本与 sha256 跟过来 |
| **给第三方插件补一份实测记录** | **本仓库** | `node scripts/market-review.mjs <owner/repo \| npm 包名 \| 插件 id>` → 真机隔离环境实测 → 填 `review.*` 与 `peer*` → 写进 `catalog/overrides/reviewed.json` → `node scripts/sync-catalog.mjs` → `node scripts/sync-catalog.mjs --check` |
| **报告某个插件已失效 / 建议下架** | 本仓库 | 开 Issue。带人工结论的条目**不会被自动删除**（只有 `tier=community` 且来自公开索引的条目会随上游消失而删除），需要人工改覆盖层 |

来源标注义务（作者 / 上游 / 许可，查不到就写「未注明」并说明核实过程）见
[`CONTRIBUTING.md` 第二节](../CONTRIBUTING.md#sources)；
收录一条 `reviewed` 的完整步骤见 [`docs/目录同步.md` §七](./目录同步.md#add-reviewed)。

## 六、怎么安装这些内容

**不需要手动找 tarball。** 装好引导插件 `dsh-plugins-market` 之后，在 GUI 左侧「插件市场」里
按需点装即可 —— 面板会在装前跑兼容性闸门，失败自动回滚，并始终给出一份可复制的手动安装命令。

- 安装流程：[`README-安装说明.md`](../README-安装说明.md)
- 自研插件的手动下载地址与 sha256：集合仓库的
  [`README.md`](https://github.com/HaydenSmith1121/dsh-plugin-collection/blob/main/README.md)
  与 [`manifest.json`](https://github.com/HaydenSmith1121/dsh-plugin-collection/blob/main/manifest.json)
