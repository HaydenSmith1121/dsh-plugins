# 目录结构

**[← 回到首页](../README.md)**

本仓库按「**分发层**」的思路组织：`plugins/` 是市场点装时真正读取的位置，
`collection/` 是不可变快照，`catalog/` 是市场界面的目录数据，
`scripts/` 负责检测、安装与校验。

---

## 二、三层目录，三种职责

| 目录 | 回答什么问题 | 可变性 | 谁在读它 |
|---|---|---|---|
| `plugins/<目录名>/<dsh 版本>/` | 「**该装哪一套**」 | 可增可换 | 安装脚本、插件市场 |
| `collection/snapshots/<目录名>/<插件版本>/` | 「**当时收录的是哪一版**」 | **不可变** | 收录校验、审计 |
| `plugins-src/<插件>/` | 「**源码长什么样**」 | 正常开发 | 开发者 |

> **`plugins/` 的那一层是 dsh 运行时版本，不是插件版本。**
> 含义是「这套 tarball 适配 dsh 的哪个版本」。装哪套由你机器上的 dsh 版本决定，
> 安装脚本会自动选。
>
> **`collection/snapshots/` 的那一层则是插件版本** ——
> 它答的是另一个问题：「当时收录的是哪一版」。两者含义相反，是刻意的，详见
> [`collection/SPEC.md`](../collection/SPEC.md) §2.1。

## 三、机器可读的几份数据

| 文件 | 谁维护 | 作用 |
|---|---|---|
| `compatibility.json` | 人工 + 实测 | 版本兼容矩阵的唯一事实来源：每个 runtime 支持哪些插件、bundle 顺序、peer 结论 |
| `collection/manifest.json` | **脚本生成，禁止手写** | 收录快照清单 + 逐条 sha256 |
| `collection/collection-notes.json` | 人工 | 版本核实结论与收录理由（唯一需要人写的收录文件） |
| `catalog/verified-meta.json` | 人工 | 市场「已验证」层的展示文案 |
| `catalog/curated.json` | 人工 | 市场「已审核」层的条目与审核证据 |
| `profile-config/profile-bundles.yaml` | 人工 | web profile 的 bundle 层级顺序 |

> 改 `plugins/` 的目录结构时，**`compatibility.json` 必须同步改**，
> 否则市场不会把插件列出来（光把 tarball 放进去是不够的）。
> 入库的完整动作见 [`CONTRIBUTING.md` 第四节](../CONTRIBUTING.md#四新增一个插件)。
