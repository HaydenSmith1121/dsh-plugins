# 目录结构

**[← 回到首页](../README.md)**

自 0.4.0（**市场与插件分离**）起，本仓库只有三件事：**目录**、**安装入口**（市场面板 + 引导脚本）、
**每日刷新**。插件的字节、版本与源码都在另一个仓库
[`HaydenSmith1121/dsh-plugin-collection`](https://github.com/HaydenSmith1121/dsh-plugin-collection)。

因此这里**一个插件一个配置文件**（`catalog/plugins/<slug>.json`），而不是几个大 JSON；
`catalog/index.json` 只是由它们**派生**出来的、给列表页读的轻量索引。

## 一、完整目录树

```none
dsh-plugins/
├─ README.md                        # 首页：两个仓库的分工 / 快速开始 / 文档地图 / 贡献入口
├─ README-安装说明.md                # ★ 安装教程（唯一的安装文档，自包含）
├─ README-开发环境隔离.md            # ★ 开发插件时的环境隔离（可移植到新设备）
├─ CONTRIBUTING.md                  # ★ 贡献规范：配置文件规则 / 来源标注 / 收录流程 / PR 检查清单
├─ compatibility.json               # ★ 机器可读的**运行时矩阵**（不再含逐插件记录，见第三节）
├─ 启动-调试环境-3090.cmd            # ★ 双击即起隔离调试环境（3090），不影响日常的 3080
├─ .github/workflows/
│  ├─ sync-catalog.yml              # ★ 每日 18:00 UTC 采集目录并提交（内容没变就不提交）
│  └─ verify.yml                    # push / PR 上的只读校验：目录自洽 + 市场插件可构建
├─ catalog/                         # ★ 目录：市场唯一的事实来源
│  ├─ plugins/<slug>.json           #   一个插件一份配置（当前 7496 份）：版本 / star / 仓库 / 安装方法
│  ├─ index.json                    #   由上面派生的索引（列表页只读这一份，禁止手写）
│  └─ overrides/                    #   人工覆盖层
│     ├─ curated.json               #     人工核对过的第三方条目：安装规格 / peer 结论 / 实测记录（当前 7 条）
│     └─ self.json                  #     市场插件自己那一行（版本与 sha256 由采集脚本反推）
├─ docs/                            # 深度文档（首页只放链接，正文在这里）
│  ├─ 目录结构.md                    #   本文件：仓库里都有什么、怎么分层
│  ├─ 插件清单与来源.md              #   目录配置文件的**格式**：每个字段的含义与来源
│  ├─ 目录同步.md                    #   每日同步端到端：四路合并 / 版本解析 / 时间戳 / 本地怎么跑
│  ├─ 收录说明.md                    #   目录不分级意味着什么；旧的「收录快照」内容搬去了哪里
│  ├─ 版本兼容矩阵.md                #   每个 dsh 版本支持到什么程度 + 两条必须记住的规矩
│  └─ 注意事项.md                    #   兼容策略 / 踩过的坑 / 卸载回滚
├─ scripts/
│  ├─ sync-catalog.mjs              # ★ 目录的采集与生成器（唯一会写 catalog/ 的脚本）
│  ├─ lib/catalog-format.mjs        #   配置文件的形状：字段 / slug 规则 / 索引怎么派生
│  ├─ lib/version-resolve.mjs       #   版本号与收藏量的采集器（npm registry + 批量 GraphQL）
│  ├─ preflight.mjs                 #   环境预检（只读）：检测 + 判定 + 给出行动方案
│  ├─ install.mjs                   #   安装执行器：**只装引导插件**（市场面板）
│  ├─ verify.mjs                    #   安装后四步校验（版本 / 依赖层 / 装配层 / 真实启动）
│  ├─ market-review.mjs             # ★ 第三方条目核对助手：探测候选包 → 产出实测草稿
│  ├─ dev-env.mjs                   # ★ 开发环境隔离（init/status/doctor/web/install…）
│  ├─ install.ps1 / install.cmd     # Windows 一键安装入口（薄壳，落仓库到 ~/.dsh-plugins）
│  ├─ install.sh                    # macOS / Linux 一键安装入口（薄壳）
│  └─ dev-env.ps1 / dev-env.cmd / dev-env.sh   # 隔离脚本的薄壳入口
├─ plugins-src/
│  └─ dsh-plugins-market/           # ★ 市场面板插件（仓库里唯一带源码的插件）
│     ├─ src/server/                #   服务器半：目录 / 闸门 / 安装器 / profile / 进度 …
│     ├─ src/client/app.js          #   客户端半（不打包、不转译，直接可用）
│     ├─ build.mjs                  #   ★ 构建：生成包内兜底目录 + 打 tarball 到 plugins/
│     └─ test/                      #   单测与冒烟自检（CI 里跑）
├─ plugins/                         # 本仓库托管的产物：**只有市场插件自己**
│  └─ dsh-plugins-market/
│     └─ 0.1.6-alpha.1/             #   ★ 这一层是 dsh 运行时版本，不是插件版本
│        ├─ dsh-plugins-market-0.3.0.tgz         # 上一版产物（已发布，保留）
│        ├─ dsh-plugins-market-0.3.0.tgz.sha256
│        ├─ dsh-plugins-market-0.4.0.tgz         # ★ 当前产物
│        └─ dsh-plugins-market-0.4.0.tgz.sha256  # 校验和边车文件（权威值）
├─ profile-config/
│  └─ profile-bundles.yaml          # web profile 的 bundles 顺序导出快照（市场分离前导出的，见第四节）
├─ settings/
│  └─ settings.yaml                 # 默认模型 / 依赖目录等设置快照（不含密钥）
└─ assets/
   └─ hero-everything-is-a-plugin.svg   # 首页配图（纯矢量）
```

**不在这里的东西**（都在集合仓库）：插件的 tarball、每个插件的 `plugin.json`、不可变快照
`snapshots/<id>/<版本>/`、`dsh-ark-plans` 与 `dsh-memory` 的源码、以及由它们派生的 `manifest.json`。

> 已删除的历史路径：`collection/`、`catalog/verified.json`、`catalog/verified-meta.json`、
> `catalog/curated.json`、`scripts/build-collection.mjs`、`scripts/lib/verified-catalog.mjs`，
> 以及 `plugins/` 下除市场插件以外的全部 tarball。它们的内容去了哪里见
> [`收录说明.md`](./收录说明.md)。

## 二、三层目录，三种职责

| 目录 | 回答什么问题 | 可变性 | 谁在读它 |
|---|---|---|---|
| `catalog/plugins/<slug>.json` | 「**这个插件是什么、怎么装**」 | 每日采集刷新（内容变了才动） | 市场面板**安装时**按需拉取；人 review 时直接看 diff |
| `catalog/index.json` | 「**列表页该显示什么**」 | **派生**，禁止手写 | 市场面板列表页（唯一的列表数据源） |
| `catalog/overrides/*.json` | 「**哪些结论是人写的**」 | 只能由人改 | 采集脚本（`sync-catalog.mjs`） |

> **索引与配置的关系是单向的**：索引由配置派生，配置不由索引派生。
> 列表页只读索引；真要动手装的时候，市场会去拉**那一个插件自己的配置文件**，
> 按它写的 `install.method` 装 —— 读不到就**不装**，绝不拿索引字段猜一个安装方法。
> 详见[首页第三节](../README.md#catalog)。

<a name="two-layers"></a>

### `plugins/<目录名>/<dsh 版本>/` 的那一层是 dsh 版本

本仓库只剩市场插件一个产物，但目录约定没变：**`0.1.6-alpha.1` 是 dsh 运行时版本**，
含义是「这份 tarball 适配 dsh 的哪个版本」。集合仓库那边同时存在两层，含义相反：

| 路径 | 那一层是什么 |
|---|---|
| `plugins/<id>/<dsh 版本>/<包名>-<版本>.tgz` | **dsh 运行时版本**（该装哪一套） |
| `snapshots/<id>/<插件版本>/<包名>-<版本>.tgz` | **插件版本**（当时收录的是哪一版），不可变 |

别把这两层写反 —— 写反的后果是「装上了但装的是另一版」。

## 三、机器可读的几份数据

| 文件 | 谁维护 | 作用 |
|---|---|---|
| `catalog/plugins/<slug>.json` | **脚本采集 + 人工覆盖层**（`node scripts/sync-catalog.mjs`） | 逐插件的事实：版本 / `versionSource` / star / 仓库地址 / 许可 / 安装方法（0.5.0 起不再有 `tier` / `review`） |
| `catalog/index.json` | **脚本生成，禁止手写** | 由上面派生的紧凑索引：列表页只读它 |
| `catalog/overrides/curated.json` | **人工**（补的是公开索引里查不到的事实） | 安装规格 / peer 结论 / 实测记录（`notes` + `evidence`）；改完必须重跑采集 |
| `catalog/overrides/self.json` | **人工**（只写元数据，版本与 sha256 由脚本反推） | 市场插件自己那一行；它不在集合仓库的 `manifest.json` 里 |
| `compatibility.json` | **人工 + 实测** | 运行时矩阵：`requirements` / `distTags` / `inBoxBundles` / `allowBuilds` / `runtimes` |
| `profile-config/profile-bundles.yaml` | 人工（历史导出快照） | web profile 的 bundle 层级顺序；`verify.mjs` 在顺序异常时会指向它 |
| `settings/settings.yaml` | 人工 | 默认模型等设置快照（**不含**任何密钥） |

> `compatibility.json` 自 0.4.0 起**不再包含逐插件记录**（版本 / tarball / sha256）。
> 逐插件事实一律看 `catalog/plugins/<slug>.json`；自研插件的权威记录在集合仓库的
> `plugins/<id>/plugin.json`。该文件里仍保留 `runtimes[].bundles` 与 `pluginSummary`
> 两份**旧格式的包名名单**（只有名字，没有版本与 tarball）；需要判断「装了什么、是什么版本」时，
> 以目录（`catalog/`）为准。

### 两条硬规矩

- **不要手写生成物**：`catalog/index.json` 与 `catalog/plugins/*.json` 由
  `node scripts/sync-catalog.mjs` 生成；手写的会被下次采集覆盖，且
  `node scripts/sync-catalog.mjs --check`（CI 每次都跑）会直接报不一致。
- **改完人工覆盖层必须重跑采集**：改了 `catalog/overrides/*.json` 却没跑
  `node scripts/sync-catalog.mjs`，配置文件里还是旧内容，CI 一样会红。

## 四、这棵树的现状（对得上代码、也对得上数据）

| 事实 | 当前值 | 从哪看 |
|---|---|---|
| 配置文件份数 / 索引条数 | 7496 / 7496（必须相等） | `ls catalog/plugins/*.json \| wc -l`、`catalog/index.json` → `counts.total` |
| 目录分级 | **没有分级**（0.5.0 起） | 配置文件里没有 `tier`，`counts` 只有 `total` |
| 人工核对过的第三方条目 | 7 条（`dsh-web`、`dsh-api-relay-audit`、`@dsh-external/dsh-ads`、`@dsh-market/plugin`、`dsh-workbuddy-connect`、`dsh-connect-trae`、`dsh-receipt`） | `catalog/overrides/curated.json` |
| 本仓库托管的插件产物 | 只有 `dsh-plugins-market` | `plugins/` 下只有它一个目录 |
| 市场插件的源码版本 | `0.5.0` | `plugins-src/dsh-plugins-market/package.json` |
| 市场插件的产物 | `dsh-plugins-market-0.5.0.tgz` + `.sha256`（旧版 `0.3.0` / `0.4.0` 仍保留，见下） | `plugins/dsh-plugins-market/0.1.6-alpha.1/` |

> **字节由本仓库托管的那 7 条** = 集合仓库 `manifest.json` 里的 6 个插件 + 市场插件自己。
> 判据是 `install.method === 'tarball'`（0.5.0 之前写的是 `tier === 'verified'`）——
> 同一批条目，换成了一个不依赖任何分级体系的硬事实。
> 采集需要能读到集合仓库（本地同级目录、`DSH_PLUGIN_COLLECTION`，或联网拉
> `raw.githubusercontent.com`）；读不到时会明确记一句「本轮不含自研插件」继续跑，
> 见 [`目录同步.md`](./目录同步.md#local-run)。
>
> **旧版本的 tarball 保留是有原因的**：已装的 profile 里写的是 `file:` 绝对路径，
> 删掉旧包会让那份依赖悬空。等确认没有安装再清理。
>
> `profile-bundles.yaml` 是**市场分离之前**导出的快照，里面仍是旧 11 个插件的顺序与
> 已经不在本仓库的 tarball 文件名。它只作「profile 里 bundles 应该长什么样」的参考；
> 现在「profile 里实际装了哪些插件」才是 `verify.mjs` 的判据。
